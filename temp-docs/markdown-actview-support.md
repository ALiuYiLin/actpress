# 「Use Vue in Markdown」→「Use ActView in Markdown」重构方案

> 目标：VitePress 文档中「在 Markdown 里用 Vue」的能力迁移为「在 Markdown 里用 ActView」，
> 并同步改写 `docs/en/guide/using-vue.md` 等文档。
> 状态：方案 v2（未改动代码）。
> v2 变化：放弃模板编译器（无 `{{}}`/指令）；采用「双 script 块」+「正文渲染为 JSX」；
> 组件引用支持属性透传。

---

## 1. 背景与现状

### 1.1 原版（Vue）如何工作

md → `markdownToVue` → Vue SFC（`<script setup>` + `<template>`）→ `@vitejs/plugin-vue` 编译。
md 里可使用 Vue 模板能力（插值/指令/组件/`<script setup>`）。

### 1.2 ActView 现状（markdownToActView）

```
md → markdownToActView → createElement 调用链（纯静态 VNode）
   + <script setup> 转 setup 体
```

| 能力 | 现状 |
|---|---|
| `<script setup>` | ✅ `extractSetupBody`：import 提升、`vue`→`actview` 改写、`export const` 降级 |
| `{{ }}` / `v-if` / `v-for` / `v-html` | ❌ 字面渲染（无模板编译器，**维持不支持**） |
| 内联组件 | ❌ 渲染为字符串标签 |
| 正文渲染形态 | createElement 调用链（静态） |

## 2. 目标（ActView 语义，非 Vue 模板语义）

1. **md 支持双 script 块**：
   - `<script lang="ts" setup>` —— 页面状态/逻辑（进入默认组件 setup 函数体）
   - `<script lang="tsx">` —— 可复用的**具名导出组件函数**（模块顶层，如 `export function MyButton`）
2. **正文**：静态 HTML + **大写开头标签 = 组件引用**（解析为具名导出函数，支持属性透传）。
3. **生成形态**：**.tsx 模块**（正文渲染为 JSX，不是 createElement 链）。
4. **无模板编译器**：`{{}}`/`v-*` 在正文中保持字面（不解析）；文档明确标注不支持。
5. 文档改写：`using-vue.md` → `using-actview.md`。

## 3. md 写法（目标）

```md
---
title: Demo
---

<script lang="ts" setup>
import { ref } from 'actview'

const count = ref(0)
const inc = () => count.value++
</script>

<script lang="tsx">
export function MyButton() {
  return <button className="mybutton">Click</button>
}
</script>

# 标题

<MyButton size="lg" />

<p>count: {count.value}</p>   <!-- 注意：不是 {{ }}，正文是 JSX 上下文 -->
```

## 4. 生成形态（.tsx 模块）

```tsx
// generated by markdownToActView
import { defineComponent } from 'actview'
// 两个 script 块的 import 全部提升到模块顶层（现有机制复用；vue→actview 改写）

// ---- <script lang="tsx> 具名导出（原样保留）----
export function MyButton() {
  return <button className="mybutton">Click</button>
}

// ---- 默认页面组件 ----
export default defineComponent(function () {
  // ---- <script lang="ts" setup> 内容（进 setup 函数体，非顶层——避免全局单例）----
  const count = ref(0)
  const inc = () => count.value++

  return function () {
    // ---- md 正文 → JSX（HTML 序列化升级为 JSX 序列化）----
    return (
      <div>
        <h1>标题</h1>
        <MyButton size="lg" />
        <p>count: {count.value}</p>
      </div>
    )
  }
})
```

**要点**：
- setup 代码必须进 `defineComponent` 的 setup 函数体（模块顶层会变成全局单例，路由切换状态串）。
- 生成的 `.tsx` 走 vite 既有管线：esbuild/rolldown JSX（automatic runtime `@actview/jsx`）
  + `actviewPlugin`（Babel 把 `export function MyButton` 等裸函数组件包成 `defineComponent`）。

## 5. 方案设计

### 5.1 script 块解析（复用/扩展现有 `extractSetupBody`）

| 块 | 处理 |
|---|---|
| `<script lang="ts" setup>` | 内容 → setup 函数体；`export const` 降级为 `const`；`export default` 注释 |
| `<script lang="tsx">` | 内容 → 模块顶层（原样）；**收集具名导出名集合**（`export function X` / `export const X` / `export { X }`）用于组件解析 |
| 普通 `<script>` | 内容 → 模块顶层（与 tsx 块合并）；不收集导出 |
| `<style>` | 不支持，编译期警告（Vue SFC 语义，ActView 无 scoped style 管线） |

- 两个/多个块的 **import 语句统一提升到顶层**（去重），其余按上述位置放置。
- `vue` / `@vueuse/*` import 改写为 `actview`（现有逻辑）。

### 5.2 正文 HTML → JSX 序列化

复用现有 HTML 解析器（标签/属性/实体解码/注释丢弃），**输出从 createElement 链改为 JSX 源码**：

| HTML | JSX 输出 | 说明 |
|---|---|---|
| `class="a b"` | `class="a b"` | ActView JSX 用 `class`（core 同时支持 class/className） |
| `style="color:red"` | `style="color:red"` | 保留字符串（ActView setProp 支持 cssText） |
| `disabled` | `disabled` | 布尔属性原样 |
| `id` / `data-*` / `aria-*` 等 | 原样 | |
| `on*`（字符串事件） | **丢弃 + 警告** | 静态 HTML 里的字符串事件在 JSX 中是字符串值，语义错误；提示改用 setup 里绑定或组件 |
| `foo="bar"` | `foo="bar"` | 普通属性字符串 |
| `<br>` `<img>` | `<br />` `<img />` | 自闭合/void 元素 |
| 文本 | 文本节点；`{` `}` `<` 等 JSX 特殊字符需转义 | 正文中 `{{}}`/`v-*` 保持字面（不解析） |
| 注释 `<!-- -->` | 丢弃 | 现有逻辑 |

**组件标签解析**（大写开头）：
- `<MyButton size="lg" />` → `<MyButton size="lg" />`——**属性透传**：字符串属性 → JSX 字符串；
  无属性 → `<MyButton />`。
- 标签名在「具名导出集合」中 → 组件引用；不在 → **编译期警告**（渲染为字符串标签的兜底行为？
  建议：警告 + 渲染为字符串标签，作者自查）。
- 非大写标签（含 `my-button`、`svg` 等）→ 普通元素字符串。

### 5.3 裸函数组件转换（关键依赖）

`export function MyButton() { return <button .../> }` 是**裸函数**，ActView 渲染器
`isComponentVNode` 只认 `{ __setup }`。两条路径：

- **路径 A（推荐）**：生成的 .tsx 走 vite 的 `actviewPlugin`（Babel：最后 return 是 JSX 的函数
  → 包 `defineComponent`）。需确保 md 虚拟模块 id 以 `.tsx` 结尾且被插件处理。
- **路径 B（node 侧直接包裹）**：markdownToActView 生成时对具名导出做 AST 级包裹
  （复用 `@actview/plugin` 的 Babel 插件或直接文本变换）——不依赖 vite 插件顺序。

> 路径 A 依赖现有 dev/build 管线（plugin.ts 已配 `actviewPlugin` + esbuild jsx）；
> 需验证 md 生成的模块确实经过该插件（此前 `.tsx` 带 `?t=` query 时插件已处理，
> 见 bug-fix-log）。若管线不可靠，退路径 B。

### 5.4 生成器改动位置

- `src/node/markdownToActView.ts`：
  - `createActViewSrc`：改输出 .tsx 模块骨架（双 script 块 + defineComponent setup + JSX render）。
  - `serializeHtmlToVNode`（或新增 `serializeHtmlToJsx`）：HTML → JSX 源码。
  - 新增：具名导出集合收集、组件标签解析、JSX 文本转义。
- `plugin.ts`：md transform 返回 .tsx 模块；确认 actviewPlugin 覆盖（路径 A）。

| 文件 | 改动 |

> docs 其余 `{{}}`/`v-*` 在**代码块示例**内（展示语法），不改写。

## 7. 实施步骤（每步独立 commit + 单测）

1. **生成形态改造**：双 script 块解析 + .tsx 模块骨架（正文仍静态）——单测断言生成源码结构。
2. **HTML → JSX 序列化**：正文改 JSX（静态元素/文本/属性），替换 createElement 链——单测
   （标签/属性/自闭合/文本转义/on* 警告）。
3. **组件引用**：具名导出集合 + `<MyButton/>` 解析 + 属性透传——单测（有/无属性、未知组件警告）。
4. **裸函数组件转换验证**：路径 A（vite 管线）实测 dev/build；失败则路径 B（node 侧包裹）。
5. **错误提示**：不支持语法（`<style>`、`{{}}` 教学提示、on* 字符串）编译期警告。
6. **文档改写**：using-vue → using-actview + 链接（独立 commit）。
7. **验证**：`pnpm test:unit`、`tsc` 双端、docs dev 冒烟（组件页）、`vitepress build` 静态产物。

## 8. 风险与开放问题

| 风险/问题 | 说明 |
|---|---|
| 生成 .tsx 的 vite 管线 | md 虚拟模块须过 actviewPlugin（裸函数组件）；需实测，失败退路径 B |
| JSX 文本转义 | 正文文本含 `{`/`}`/`<` 需转义（`{'{'}` 等）；实体解码与 JSX 转义顺序 |
| 具名导出类型 | `export const X = () => <JSX/>` 也收集（箭头函数组件）；`export default` 在 tsx 块中如何处理（与页面默认组件冲突 → 警告/忽略） |
| on* 字符串属性 | 丢弃 + 警告（避免 JSX 里变成字符串值） |
| 多 script 块顺序 | import 提升后，tsx 块具名导出在顶层、setup 块内容在 setup 体内——相对顺序对引用无影响 |
| `{{}}` 教学 | 正文中保持字面；文档明确「ActView 不支持模板插值，用 setup 变量 + JSX 表达式」 |

## 9. 结论

- **形态**：md = 双 script 块（tsx 具名组件 + ts setup 逻辑）+ 正文（静态 HTML + JSX 组件引用）。
- **无模板编译器**：`{{}}`/`v-*` 不支持（明确文档化）。
- 生成 .tsx 模块，正文 JSX 序列化，组件属性透传，裸函数组件由 actviewPlugin（或 node 侧）包裹。
- 工作量：双 script 块（小）→ JSX 序列化（中）→ 组件解析（小）→ 管线验证（中）→ 文档（小）。

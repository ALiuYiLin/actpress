# ActPress 的 Markdown 编译原理：md → tsx → html

> 本文说明 ActPress（VitePress 的 ActView 重构版）如何把一个 `.md` 文件编译成
> 可交互页面：`md → .tsx 模块 → 浏览器可执行 JS → html`。
> 核心思想一句话：**md 就是一个 tsx 文件**——`<script>` 块是模块顶层代码（共享作用域），
> 正文是页面组件的 JSX（静态 HTML + 组件引用）。

---

## 1. 总览：三段式管线

```
.md 文件
   │  ① createMarkdownRenderer（markdown-it + 插件）
   ▼
静态 HTML + 提取出的 <script lang="tsx"> 块
   │  ② markdownToActView（createActViewSrc）
   ▼
.tsx 模块源码（script 块提升顶层 + 页面组件 defineComponent + 正文 JSX）
   │  ③ plugin.ts 编译管线（esbuild 转 JSX + @actview/plugin 包组件）
   ▼
浏览器可执行 JS
   │  ④ 运行期：createApp().mount() 渲染 / 构建期 renderToString 静态生成
   ▼
html
```

| 阶段 | 输入 | 输出 | 关键实现 |
|---|---|---|---|
| ① markdown 解析 | `.md` | HTML + `env.sfcBlocks` | `markdown.ts` 的 `tsxSfcPlugin` |
| ② 模块生成 | HTML + sfcBlocks | `.tsx` 源码 | `markdownToActView.ts` 的 `createActViewSrc` |
| ③ 编译 | `.tsx` 源码 | 可执行 JS | `plugin.ts` 的 `compileActViewSrc` |
| ④ 渲染 | JS 模块 | html | 浏览器 `createApp().mount()` / 构建期 `renderToString` |

---

## 2. ① markdown 解析：HTML + script 块提取

`createMarkdownRenderer`（markdown-it + 各种插件）把 md 渲染成静态 HTML。
关键差异在于 **`tsxSfcPlugin` 替代了原版 Vue 的 `sfcPlugin`**：

- **提取**：独占一行的 `<script lang="tsx">`（含 `<script lang="tsx" setup>`）和
  `<script setup>` → 放入 `env.sfcBlocks.scripts`，从 HTML 中移除。
- **其余所有标签**（普通 `<script>`、`<style>`、custom block 等）**一律留在 HTML
  原样渲染**——它们不是模块代码，而是页面的一部分（"其他标签当 HTML"）。

```md
# 标题

<script lang="tsx">
const count = ref(0)              // ← 被提取到 env.sfcBlocks.scripts
</script>

<script lang="tsx">
export function Counter() {       // ← 被提取
  return <button onclick={() => count.value++}>{count.value}</button>
}
</script>

<Counter />                       // ← 留在 HTML（大写标签 = 组件引用）

<style>
.counter-btn { color: red }       // ← 留在 HTML，当普通元素渲染
</style>
```

## 3. ② 模块生成：md → .tsx

`createActViewSrc(html, sfcBlocks, pageData)` 把「HTML + script 块」拼成一个 `.tsx` 模块：

### 3.1 所有 `<script>` 块内容提升到模块顶层（共享作用域）

```
// ---- <script> blocks (hoisted to module top; shared scope) ----
import { ref } from 'actview'     // 各块的 import 合并去重
const count = ref(0)
export function Counter() {
  return <button onclick={() => count.value++}>{count.value}</button>
}
```

- **不区分** `<script lang="tsx">` / `<script setup>` / 普通 `<script>` —— 都是顶层代码。
- 多个块的 **import 自动去重**（同源同名只保留一条，避免 `Duplicate declaration`）。
- `export default`（用户写的）会被注释掉——页面默认组件由编译器生成。

### 3.2 页面默认组件：defineComponent 包裹正文 JSX

```
import { defineComponent } from 'actview'   // 用户已 import 则不重复添加
export default defineComponent(function () {
  return () => (
    <div>
      <h1>标题</h1>
      <Counter />
    </div>
  )
})
```

- 正文 HTML → JSX（`serializeHtmlToJsx`）：静态元素原样、`<Counter />` 解析为组件引用。
- **为什么不用裸函数**：`@actview/plugin` 的 Babel 只包裹「大写命名、return JSX 字面量」
  的函数；匿名 default 组件不会被包，浏览器端渲染器只认 `{ __setup }`，裸函数会崩
  （`InvalidCharacterError`）。所以页面组件**显式 defineComponent 包裹**。
- `__pageData` 契约：`export const __pageData = JSON.parse(...)`，主题用 `useData()` 读取。

### 3.3 完整产物示例

```tsx
// generated by markdownToActView
import { ref } from 'actview'

const count = ref(0)

export function Counter() {
  return <button onclick={() => count.value++}>{count.value}</button>
}

export const __pageData = JSON.parse("{\"title\":\"标题\",...}")

import { defineComponent } from 'actview'
export default defineComponent(function () {
  return () => (
    <div>
      <h1>标题</h1>
      <Counter />
    </div>
  )
})
```

## 4. ③ 编译管线：.tsx → 可执行 JS

`plugin.ts` 的 `compileActViewSrc` 两步：

1. **esbuild 转 JSX**（`transformWithEsbuild`，`loader: 'tsx'`，automatic runtime
   `@actview/jsx`）：`<button>` → `jsx("button", {...})`。
2. **`@actview/plugin`（Babel）包裸函数组件**：把「return JSX / return `_jsx()` 调用」
   的大写命名函数 → `defineComponent(function () { return () => <JSX/> })`。

> ⚠️ **边界**：`export function X() { return <JSX/> }` 会被自动包裹；
> 但 `export function X() { return 变量 }`（返回标识符）无法静态判断是否为组件，
> 需要用户**显式 `defineComponent` 包裹**。

## 5. ④ 渲染：JS → html

| 场景 | 机制 |
|---|---|
| **浏览器端**（dev / 客户端挂载） | `createApp(pageComponent).mount('#app')` → 渲染器把组件树 patch 成真实 DOM |
| **构建期**（静态生成 / SSG） | `renderToString(vnode)` 把组件树序列化为 HTML 字符串，写进 `.html` 文件 |

两条路径共用同一套组件模型（`defineComponent` → `{ __setup }`），所以
「构建期预渲染的 HTML」与「浏览器端挂载的交互」完全一致。

## 6. 使用场景

### 6.1 单页交互组件（最典型）

md 里既要页面逻辑，又要内联组件并让组件操作状态：

```md
<script lang="ts" setup>
import { ref } from 'actview'
const count = ref(0)
</script>

<script lang="tsx">
export function Counter() {
  return <button class="counter-btn" onclick={() => count.value++}>{count.value}</button>
}
</script>

<Counter />

<style>
.counter-btn { padding: 8px 20px; background: #42b883; color: #fff; }
</style>
```

### 6.2 页面级逻辑 + 复用组件

只被当前页使用的组件直接定义在 tsx 块并引用，无需单独建文件。

### 6.3 属性透传与导入组件

```md
<script lang="tsx">
import { ModalDemo } from '../components/ModalDemo'
export function MyButton(props: any) {
  return <button className="mybutton" {...props}>Click</button>
}
</script>

<MyButton size="lg" />
<ModalDemo />
```

### 6.4 `<script lang="tsx" setup>` 写 JSX 变量

```md
<script lang="tsx" setup>
import { defineComponent } from 'actview'
const greeting = <strong>Hello</strong>
export const Greeting = defineComponent(function () {
  return () => greeting
})
</script>

<Greeting />
```

## 7. 不支持的能力（设计取舍）

| 能力 | 状态 |
|---|---|
| 正文 `{expr}` JSX 表达式（如 `{count.value}`） | ❌ 作为字面文本渲染；动态内容放组件内部 |
| `{{ }}` 插值 | ❌ 字面文本 |
| `v-if` / `v-for` / `v-html` / `v-bind` / `v-on` 指令 | ❌ 字面属性 |
| 字符串 `onclick="..."` 属性 | ❌ 丢弃 + 警告（JSX 事件必须是函数） |
| `<style scoped>` | ⚠️ `<style>` 原样渲染进正文（全局生效，无 scoped） |
| `export function X() { return 变量 }` | ⚠️ 需显式 `defineComponent`（无法静态识别） |

## 附：涉及文件

| 文件 | 职责 |
|---|---|
| `src/node/markdown/markdown.ts` | markdown-it 配置 + `tsxSfcPlugin`（只提取 tsx/setup script 块） |

| `src/node/plugin.ts` | `compileActViewSrc`：esbuild 转 JSX + `@actview/plugin` 包组件 |

| `src/client/app/ssr.ts` | 构建期 `renderToString` 静态生成 |

# markdownToVue → markdownToActView 重构记录

> 将 VitePress 的核心编译链路由 Vue SFC 产物切换为 ActView 模块产物。
> 本文记录重构的方式、原理与取舍，供后续维护与在 ActView 项目（`E:\code3\JSX-Demo`）中接入时参考。

---

## 1. 背景与目标

VitePress 的 markdown 编译管线以 `src/node/markdownToVue.ts` 为核心：

```
.md 文件
   │  createMarkdownRenderer（markdown-it + 插件：高亮/容器/表格/链接/锚点…）
   ▼
渲染出的静态 HTML + 抽取出的 SFC 块（<script> / <style> / custom block）
   │  markdownToVue.ts
   ▼
Vue SFC 字符串（vueSrc）：<script> + <template><div>{html}</div></template> + <style>
   │  @vitejs/plugin-vue 编译
   ▼
Vue 组件模块
```

目标：把这条链路的最后一环（`markdownToVue.ts`）改造成 **`markdownToActView`**，输出 **ActView 可执行的纯 JS 模块**（VNode 树），使 VitePress 的 markdown 渲染能力可以直接服务于 ActView 生态（`E:\code3\JSX-Demo`，一个类 React 的 JSX 响应式框架，VNode 由 `jsxFactory` 构造、`renderer.ts` 渲染）。

ActView 与 Vue 的关键差异决定了改造方向：

| | Vue | ActView |
|---|---|---|
| 组件定义 | SFC / options API / composition API | `defineComponent(setup)`，`setup(props)` 返回 render 函数 |
| 模板 | `<template>` 编译器 | 无 template 编译器，只有 JSX / `createElement` |
| 渲染单元 | 编译后的 render 函数 | VNode（`{ $$typeof, type, key, ref, props }`） |
| HTML 静态内容 | 模板编译器内联处理 | 需要先转成 VNode 树 |

---

## 2. 重构后的产物形态

`createMarkdownToActViewRenderFn` 与旧版**骨架完全一致**（缓存、deadLinks 校验、pageData 推导、transformPageData、git 时间戳等逻辑零改动），只替换了"最后拼装"的部分：`vueSrc` → `actViewSrc`。

真实渲染 `# Hello` + `<script setup>` 的输出：

```js
// generated by markdownToActView
import { defineComponent } from "actview"
import { createElement } from "@actview/jsx"
import { ref } from 'actview'          // <script setup> 的 import 被提升到模块顶层
export const __pageData = JSON.parse("{\"title\":\"Hello\",...}")   // 契约不变：主题用 useData() 读取
export default defineComponent(function (props) {
  // ---- <script setup> ----
  const count = ref(0)                 // setup 体（ActView 同名 API 兼容）
  return function () {
    return createElement("div", null,
      createElement("h1", { "id": "hello", "tabindex": "-1" },
        "Hello ",
        createElement("a", { "class": "header-anchor", "href": "#hello", "aria-label": "Permalink to “Hello”" }, "\u200b")))
  }
})
```

与 Vue 版的对应关系：

| Vue SFC 产物 | ActView 产物 |
|---|---|
| `<script>` 注入 `__pageData` | 模块顶层 `export const __pageData = JSON.parse(...)`（契约不变） |
| `<template><div>{html}</div></template>` | `return function () { return createElement("div", null, ...VNode树) }` |
| `<style>` 由 SFC 编译为 CSS asset | 运行时注入 `<style>` 标签（见 3.3） |
| 用户 `<script setup>` 由 plugin-vue 编译 | 用户代码作为 setup 函数体（见 3.2） |
| plugin-vue 编译 SFC | **无 JSX 语法、无 SFC**，纯 JS 可直接由 esbuild 编译 |

## 3. 核心原理

### 3.1 HTML → VNode 序列化（`serializeHtmlToVNode`）

这是本次重构的核心难点。ActView 没有 template 编译器，markdown-it 渲染出的 HTML 字符串无法直接进入 VNode 树。方案是 **在 node 侧（编译期）把 HTML 解析成 `createElement` 调用链**：

- 优点：浏览器端零运行时解析开销；产物是纯静态表达式，SSR / 静态构建天然友好；与 ActView 渲染器（string 标签 / Fragment / Text 三类节点）完全兼容。
- 输出：`createElement("div", null, ...children)`，根节点用 `<div>` 包裹，与旧版 `<template><div>{html}</div></template>` 保持一致。

**Tokenizer 设计**（递归下降 + 栈）：

```
扫描 HTML 字符串，维护一个节点栈：
  '<' 分支：
    '<!--'            → 跳过注释
    '<!' / '<?'       → 跳过 DOCTYPE / CDATA / 处理指令
    '</tag>'          → 弹栈（从栈顶向下找最近的同名标签，对未闭合标签容错）
    '<tag ...>'       → 解析开标签（标签名 + 属性 + 自闭合标记）
                        非自闭合且非 void 元素 → 入栈；否则作为叶子
  其他字符            → 收集为文本，直到下一个 '<'
```

**文本节点处理**：

- 相邻文本节点**合并**（与浏览器 innerHTML 的文本节点合并行为一致，如 `a<!--c-->b` → `"ab"`）。
- `<pre>` 祖先内部的文本**原样保留**（含首尾空白，代码块内容不能丢）；其余纯空白文本**丢弃**（避免产生多余空白文本节点）。

**属性处理**：

- 属性名统一 `JSON.stringify` 引号包裹（`"aria-label"`、`"data-x"` 含特殊字符也能作为合法对象 key）。
- 属性值**解码实体**（`&amp;` → `&`）；无值属性（`<input disabled>`）→ `true`。
- 布尔/字符串语义与浏览器一致：`class`/`style`/`value` 等由 ActView `setProp` 走 property 分支，其余 `setAttribute`。
- **`on*` 字符串属性被过滤**：ActView 的 `setProp` 把一切 `on` 开头的 prop 当作事件处理器（`addEventListener`），静态 HTML 里的 `onclick="..."` 字符串会导致运行时 `invoker.value(e)` 抛出 TypeError。Vue 模板里这类属性是普通 attribute，两者语义不同，因此编译期直接丢弃（如需事件绑定，在 `<script setup>` 中用 JS 构造）。

**实体解码（`decodeEntities`）**：

- 单遍解码（不做二次解码，`&amp;lt;` → `&lt;` 字面文本），与浏览器一致。
- 支持数字实体（`&#8203;`、`&#x1F600;`，含非法码点容错）与一张覆盖 HTML4 常用命名实体表（`&nbsp;`、`&copy;`、`&mdash;`…）；未知命名实体原样保留。
- 为什么要解码：markdown-it 渲染出的 HTML 里文本/属性值是转义后的实体（`escapeHtml` 输出 `&amp;` `&lt;` 等，锚点插件输出 `&#8203;`）。若不解码，`createTextNode("&amp;")` 会显示字面 `&amp;`，与浏览器解析该 HTML 的结果不一致。

### 3.2 `<script setup>` 与组件模型映射（`extractSetupBody` / `createActViewSrc`）

ActView 组件模型：`defineComponent(setup)` 返回 `{ __setup }`，挂载时 `render = __setup(props)`，`render()` 返回 VNode（见 `mountComponent.ts`）。因此：

```js
export default defineComponent(function (props) {
  // ← 用户 <script setup> 代码在这里（setup 只执行一次）
  return function () {
    return createElement(...)   // ← render，响应式变化时重跑
  }
})
```

Vue 的 `<script setup>` 与 ActView setup 体之间需要做语义映射：

| Vue `<script setup>` 写法 | ActView 处理 |
|---|---|
| `import ... from '...'` | **提升到模块顶层**（函数体内不允许 import） |
| `export { a } from '...'`（re-export） | 提升到模块顶层 |
| `export const/function/class/...` | 去掉 `export` 前缀，降级为 setup 内普通声明 |
| `export default {...}` | 注释掉并说明（ActView 无 options API，组件由本模块生成）；**跨行对象整体注释**，避免残留孤立的 `}` |
| 本地 `export { a, b }` | 注释掉并说明（Vue `<script setup>` 本身也不允许） |
| 顶层 `await` | 生成 NOTE 注释（ActView 的 setup 是同步调用，无法支持 async setup） |
| `import.meta.env` | 生成 NOTE 注释（`import.meta` 只能出现在模块顶层） |

**import 语句的跨行收集**：以 `import` 开头逐行累积，直到括号深度归零且当前行不以 `{`/`,` 延续（单行 import 可无分号：`import { ref } from 'actview'`）。

**缩进**：setup 体只做**前缀缩进**（每行前加两个空格，不 trim），保留用户代码（含多行模板字符串）的相对缩进结构。

**普通 `<script>`（非 setup）**：内容拼到模块顶层（`export default` 注释掉）；**`<script client>`（MPA 模式）**：内容以注释形式保留在产物中（旧版 `processClientJS` 的 `clientJSMap` 提取机制未迁移，避免静默丢弃）。

### 3.3 style 块与 custom block

- `<style>`：内容 `JSON.stringify` 后生成运行时注入代码——`document.createElement('style')` 追加到 `head`（`typeof document !== 'undefined'` 守卫，SSR 下不注入）。
  - 与旧版的差异：旧版 SFC 编译会产出静态 CSS asset 且支持 scoped/预处理器；新版为全局运行时注入，`lang="scss"` 等预处理器不再编译。这是第一版的有意取舍（md 内 style 块绝大多数是纯 CSS）。
- custom block（如 `<i18n>`）：ActView 暂无对应机制，生成一条 `// NOTE` 注明不输出。

### 3.4 plugin.ts 接线

```ts
// 旧：transform .md → vueSrc，交给 plugin-vue（include /\.(?:vue|md)$/）
// 新：transform .md → actViewSrc（纯 JS），plugin-vue 只保留 /\.vue$/
const vuePlugin = await import('@vitejs/plugin-vue').then((r) =>
  r.default({ include: /\.vue$/, ...userVuePluginOptions })
)
// ...
if (id.endsWith('.md')) {
  const { actViewSrc, deadLinks, includes, pageData } = await markdownToActView(code, id, config.publicDir)
  // ...deadLinks 校验、HMR、pageData 通知逻辑不变...
  return processClientJS(actViewSrc, id)
}
```

- `.vue` 页面支持保留（plugin-vue include 收窄为 `.vue`）。
- `renderChunk` 中的 `createStaticVNode` 静态标记正则（针对 Vue 编译器输出）对 ActView 产物不再命中，无副作用（仅少了一项静态字符串优化）。

### 3.5 不变的契约

- `MarkdownCompileResult` 字段结构保留（`actViewSrc` 替代 `vueSrc`，`pageData`/`deadLinks`/`includes` 不变）。
- `__pageData` 导出契约不变——主题端 `useData()` / 路由端 `pageData` 消费方无需改动。
- `clearCache` / 分辨率缓存 / deadLinks 行号校验等逻辑原样保留。

## 4. 关键设计决策与取舍

| 决策点 | 选择 | 理由 |
|---|---|---|
| HTML 桥接方式 | Node 侧编译期序列化 | 无运行时解析开销、SSR 友好；替代方案（给 renderer 加 `dangerouslySetInnerHTML`）改动小但丢语义 |
| 产物是否含 JSX 语法 | 不含（纯 `createElement` 调用） | 不依赖 esbuild JSX 编译与 `actviewPlugin` Babel 转换，任意 vite 环境直接可编译 |
| import 源写死？ | `createActViewSrc(html, sfcBlocks, pageData, deps?)` 可配置，默认 `actview` / `@actview/jsx` | 消费方可通过别名 / 安装包名适配 |
| `on*` 静态属性 | 编译期过滤 | ActView 事件系统与静态 HTML 属性语义冲突，避免运行时 TypeError |
| style 注入 | 运行时全局注入 | 第一版取舍：SSR 不含样式、预处理器不编译（见 3.3） |
| `<script client>` / custom block | 注释保留 / NOTE 注明 | 避免静默丢失，机制迁移留待后续 |

## 6. 在 ActView 项目中接入

1. 消费方需能解析生成代码的 import：安装 `actview` 与 `@actview/jsx`，或在 vite `resolve.alias` 中指向 ActView 的 `packages/*/src`。
2. 主题侧：页面组件即 `defineComponent` 产物，可直接放入 `createApp(...)` / router 的 `routes[].component`；`__pageData` 通过 `import { __pageData } from '...'` 或全局读取。
3. 若包名不同，调用 `createActViewSrc` 时传 `deps` 覆盖默认值。
4. md 内 `<script setup>` 建议直接 `import { ref, computed, ... } from 'actview'`（API 同名，见 `packages/actview/src/index.ts`）。

## 7. 已知限制与后续演进

- [ ] `<script client>` 的 `clientJSMap` 提取（MPA）未迁移，目前以注释保留。
- [ ] `<style>` 运行时注入：SSR 输出不含样式；`lang="scss"` 等预处理器不编译；建议后续接入 CSS 提取或交由消费方处理。
- [ ] custom block（`<i18n>` 等）未输出。
- [ ] `renderChunk` 的 Vue 静态字符串优化对 ActView 产物不生效（纯性能）。
- [ ] 实体解码为"常用命名实体表 + 数字实体"，与浏览器对无分号 legacy 实体、`&#0;` 等的处理有细微差异（影响极小）。
- [ ] 序列化器对 HTML 里的大写组件标签（如 `<ClientOnly>`）按自定义元素处理，尚无组件标签 → 组件引用的解析通道。
